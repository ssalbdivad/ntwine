# A generic ACP backend — any Agent Client Protocol agent as an Ntwine worker

**Status:** design, 2026-09-15, written before the first line of code. Owner effort: the ntwine thread "Assess a refactor onto Herdr" (scratch `.ntwine/threads/85dcf153-9443-45be-9c43-759d9ac819d6/`). Branch `acp-backend`, lands on local `main`.

**Maintainer's brief (2026-09-15):** "having a fallback to anything that supports ACP is pretty clean. We should still maintain the richer integrations with Claude and Codex, though." So: a THIRD `BackendKind`, deliberately shallower than the two first-class ones, that runs whatever the operator has installed — OpenCode, Gemini CLI, Copilot CLI, Cursor, Kilo, Qwen, goose, Kimi — through one protocol client. No quota reader, no sub-agent tree, no provisioning, no daemon. Claude and Codex are untouched.

## What was measured before designing (2026-09-15, real wire, `/tmp/acp-probe.mjs`)

- `opencode acp` (1.18.29, installed here) speaks newline-delimited JSON-RPC 2.0 on stdio; the client speaks first. `initialize` → `loadSession:true`, `sessionCapabilities:{close,fork,list,resume}`, `authMethods:[{id:"opencode-login"}]`, `agentInfo`. `session/new {cwd, mcpServers}` → `{sessionId:"ses_…", configOptions:[{id:"model", type:"select", currentValue, options[]}]}`.
- A stdio MCP server passed in `mcpServers` (`{name, command, args, env:[]}` — `env` is an ARRAY of `{name,value}`) was initialized, listed and called by the agent. The tool surfaced to the model as `<serverName>_<tool>` (`probe_probe_echo`), and its `tool_call` carried `kind:"other"`. Codex and Claude spell the same tool `mcp__ntwine__ask`; OpenCode will spell it `ntwine_ask`.
- Updates seen in one turn: `available_commands_update`, `agent_thought_chunk`, `agent_message_chunk` (both with `messageId`), `tool_call {toolCallId,title,kind:edit|execute|other,status:pending,locations,rawInput}`, `tool_call_update {status:in_progress|completed, content:[{type:"content",content:{type:"text",text}}], rawOutput}`, `usage_update {used,size,cost}`. Prompt result `{stopReason:"end_turn", usage:{…}}`. `session/cancel` (a notification) made the in-flight prompt return `stopReason:"cancelled"`.
- OpenCode ran `write` and `bash` WITHOUT a `session/request_permission`: its own permission config decides. Ntwine must not assume a card per tool call, and must handle an agent that never asks.
- `cursor-agent acp` initializes but `session/new` fails `-32000 Authentication required` until `agent login` + `authenticate {methodId:"cursor_login"}`. 21 of 34 registry agents gate `session/new` on auth this way, so the auth error must surface as an actionable dispatch failure quoting `authMethods[].description`.

Full protocol notes (all 15 `session/update` variants, client methods, SDK API, per-agent launch commands and quirks) are in the scratch file `explore-acp-protocol.md`; the seam checklist for a third backend is in `explore-backend-seams.md`.

## Decisions

1. **Hand-roll the JSON-RPC client; do not depend on `@agentclientprotocol/sdk`.** The wire is ndjson JSON-RPC and the probe client is 60 lines. The SDK is ESM-only with a zod `^3.25||^4` peer the server does not carry, has shipped ordering bugs (#128/#143), an unhandled rejection on ENOENT before `initialize` settles (#121), and private-field type breakage across duplicate copies (#126). The Codex bridge hand-rolls for the same reasons. Ntwine needs: a bounded line reader that SKIPS unparseable lines (agents pollute stdout — the #1 operational failure), request/notify/respond, an `initialize` timeout, a spawn-failure path, and stderr kept for diagnostics. That is `backend/acp-rpc.ts`, with zod schemas in `backend/acp-types.ts` for only the fields Ntwine reads (every union stays OPEN — an unknown `sessionUpdate` is ignored, never thrown).
2. **Protocol v1 only.** 33 of 34 registry agents negotiate v1 and none negotiate the v2 draft. Update handling is written as upserts keyed by `toolCallId` so v2 becomes additive later.
3. **The bridge writes its OWN transcript.** Claude and Codex tail an on-disk JSONL the provider writes. An ACP agent's storage is its own business, so the bridge appends one JSONL per thread at `<stateDir>/acp/<ntwineSessionId>.jsonl` whose records ARE `NormalizedEvent`s (plus a header record naming the agent, the ACP session id and the cwd). `createAcpBackend().foldLine` is then `applyEvent` over that file — the tailer, board telemetry, rest/turn detection and the delivery ledger work unchanged — and a small `projectAcpTranscript` turns the same file into `TranscriptMessage[]` for the drawer. `session/load` replays history as updates; the writer suppresses the replay (it already has the file) by ignoring updates until the load response returns.
4. **Direct child, no daemon, in the spike** — superseded 2026-09-24 by `backend/acp-daemon.ts` / `acp-host.ts`, the detached host this decision left room for; a running turn now survives a restart (see ARCHITECTURE.md § ACP). As designed then: The agent is a child of the server over stdio, one per thread, alive while the thread is live. An Ntwine restart closes stdin and the agent exits (the spec's teardown); the thread resumes on its next input via `session/load` when the agent advertised `loadSession`, else via a fresh `session/new` with a logged, transcript-visible degrade note. A running turn does NOT survive a restart — the stated, accepted difference from the broker and the app-server. The host is behind one small interface (`AcpHost.spawn`) so a detached host can be added later without touching the bridge, and tests inject a fake spawn the way `codex-app-server.test.ts` does.
5. **ACP agents are PATH-resolved, never provisioned.** `runtimes.ts` stays `claude | codex`. A catalogue in `backend/acp-agents.ts` names the known agents (`id`, label, command, args, and a `detect` = the executable name), and `listAcpAgents(env)` returns the ones present on PATH; settings can add `acpAgents: [{id,label,command,args}]` for anything else. Dispatch preflights the executable and fails with an actionable message.
6. **The worker contract rides the first `session/prompt`.** ACP has no system-prompt channel. The first prompt is `[worker contract for "acp"] + scratchpad orientation + NTWINE.md block + the task`, exactly the shape the tmux era used and Codex still uses for `baseInstructions`. Follow-ups send only the text. After a `session/load` the history already carries it. The contract's `acp` variant says the ntwine tools appear under the harness's own naming (`ntwine_ask` / `mcp__ntwine__ask`) and that there is no Ntwine sub-agent dispatch.
7. **Permissions are the agent's, mirrored as cards.** `session/request_permission` → an `InteractionRequest` with `provider.kind:"acp"`: `command-approval` when `toolCall.kind==="execute"` and `rawInput.command` is a string, `file-approval` when kind is `edit|delete|move` with a location, else `permission-approval` with a preview of title + rawInput. `allowedDecisions` mirror the agent's `options` (`allow_once|allow_always` → `approve`, `reject_once|reject_always` → `deny`), ids are the agent's `optionId`s echoed verbatim. The answer replies `{outcome:{outcome:"selected", optionId}}`; a cancel, a turn end, a session release or an Ntwine restart replies `cancelled` and retires the card (fail closed, like the Claude bridge). Ntwine's own permission mode does not apply: the composer shows no permission control for an ACP thread, as it shows none for Codex.
8. **Follow-ups queue; cancel is `session/cancel`.** ACP has no steer. A follow-up during a turn is held by the bridge and sent as the next `session/prompt` the moment the current one returns; the delivery ledger records `queued` → `delivered`. Stop/interrupt sends `session/cancel` and expects either `stopReason:"cancelled"` or the -32603 "aborted" error some agents return (treated as a cancellation).
9. **The composer picks an agent as a "model".** Model already drives backend (`backendForModel`); an ACP agent is a model slug `acp:<agentId>` in a third group of the profile grid, and `backendForModel` returns `"acp"` for the prefix. Per-agent model choice (`configOptions[category=model]`) is deferred; the agent's default model is used and shown in the transcript header when the agent reports it.
10. **Storage.** `session.backend='acp'`, `session.agent_session_id` = the ACP session id, new column `session.acp_agent TEXT` (the catalogue id) added to `STORAGE_SCHEMA` and the `ensureStorageSchema` ALTER list. No bridge-private table: the session row plus the transcript file are enough to resume.
11. **Not in the spike, on purpose:** quota chips (`QuotaBar` stays `claude|codex`), sub-agents, a detached host, `fs/*` and `terminal/*` client methods (capabilities advertise none; agents then do their own I/O — the minimum viable client is `session/update` + `session/request_permission`), image prompts, `session/list` discovery of foreign sessions, per-agent model selection, hibernation (an idle ACP child costs whatever the agent costs; the release path kills it).

- Unit: the rpc client against the fake agent over REAL stdio (framing, skipped junk lines, initialize timeout, ENOENT, cancel → cancelled, permission round-trip, load replay suppression). Negative control: a fake that writes `Content-Length:` framing must produce a diagnostic and no crash.
- Fold + projection: a recorded `opencode` transcript fixture folds to the expected `FoldState` and projects to the expected `TranscriptMessage[]`.
- End-to-end through a real Ntwine (`scripts/adhoc-stack.mjs`, `ntwine-stack` skill): dispatch an `acp:opencode` thread → the worker calls `ntwine_title`/`ntwine_done` (proves MCP injection through the REAL ntwine server) → tool calls render in the drawer → a permission card appears for an agent configured to ask and its answer reaches the agent → a queued follow-up delivers after the turn → cancel stops a turn → restart the server and follow up (session/load) → the thread continues.
