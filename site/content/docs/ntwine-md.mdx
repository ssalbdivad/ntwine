---
title: NTWINE.md
description: Tell every agent in a project how you want things done.
---

`NTWINE.md` is an optional file at the root of a project. ntwine injects it into the system prompt of every thread in that project, Claude Code and Codex alike. Where it disagrees with ntwine's own defaults for how a worker goes about its job, it wins.

It's the place for anything you want every agent in the project to do, like how to land work, what to verify before calling something done, or how much to ask before acting.

```md title="NTWINE.md"
# Worker norms for this repo

- Land finished work on `main` yourself; never open a pull request.
- Run `pnpm test` before you call anything done, and say what you ran.
- Decide reversible calls yourself. Ask only before something destructive.
```

ntwine doesn't assume anything about your git workflow, so this is where you spell yours out. By default, a worker only commits, pushes or opens a pull request when your request or this file asks it to.

## Editing it

Open the agent settings next to the model picker and edit **Project instructions**. They save to `NTWINE.md` at the repo root, so you can commit and review them like any other file.

Changes take effect on the next thread you start, and on any existing thread the next time it resumes.

## Alongside AGENTS.md and CLAUDE.md

A worker still reads your `AGENTS.md`, `CLAUDE.md` and skills, the same way it would in a session you started yourself. `NTWINE.md` is just for what applies when an agent runs under ntwine.

If you want a worked example, ntwine's own repository keeps [its `NTWINE.md`](https://github.com/ssalbdivad/ntwine/blob/main/NTWINE.md).
